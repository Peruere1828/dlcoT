# 软件工具链与示例程序

来源：`software.zip`。包含 `Makefile`、`sections.ld`、`sys.h`、`sys.c`、`main.c`、`mul.c` 以及编译产物。本文保留源文件全文，并解释地址约定和编译流程。

## 1. 编译流程

本仓库的 Docker 环境：

- `iverilog:12`：Verilog 编译与行为仿真。
- `riscv32:12`：`riscv64-linux-gnu` 的 binutils 和 gcc、`gawk`、`make`、`qemu-riscv32`。binutils 和 gcc 都支持 `-march=rv32i -mabi=ilp32`，可用 `tools/riscv32/check.sh` 自检，`tools/riscv32/README.md` 有裸机 C 编译示例。

工具链前缀在示例 Makefile 里是 `riscv32-unknown-elf-`。如果用容器里的 `riscv64-linux-gnu-`，用 `make RISCV_PREFIX=riscv64-linux-gnu-` 覆盖，并显式加 `-march=rv32i -mabi=ilp32`，否则默认生成 RV64 代码。

```
main.c / sys.c / mul.c
        │  riscv32-unknown-elf-gcc
        ▼
      *.o
        │  链接，-Tsections.ld
        ▼
     main.elf
        │  objdump -d          → main.dump（反汇编，检查用）
        │  objcopy -O verilog  → main.tmp（带 @地址 的十六进制文本）
        ▼
  awk 分成代码段/数据段
        ├── main.hex     指令存储器初始化，@ 地址是字地址
        └── main_d.hex   数据存储器初始化
        │  awk 转 coe
        └── main.coe / main_d.coe  Vivado BRAM IP 初始化
```

关键参数：

- `-static -mcmodel=medany -fvisibility=hidden -Tsections.ld -nostdlib -nolibc -nostartfiles`；
- 链接入口 `-e entry`；
- 默认 `-O0`，没有优化；开 `-O2` 后必须保证 MMIO 变量有 `volatile`；
- 工具链前缀 `riscv32-unknown-elf-`，`XLEN=32`；
- 指令集应为 RV32I。若工具链默认生成 RV32IM 或压缩指令，要显式加 `-march=rv32i -mabi=ilp32`，否则 CPU 遇到 `mul`、`div` 或 16 位压缩指令会执行错误。

没有硬件乘除法时，`mul.c` 提供 `__mulsi3`、`__umodsi3`、`__udivsi3`，GCC 会把 `*`、`/`、`%` 降级成对这些函数的调用，必须一起编译链接。

## 2. `Makefile`

```make
default: all

XLEN ?= 32
RISCV_PREFIX ?= riscv$(XLEN)-unknown-elf-
RISCV_GCC ?= $(RISCV_PREFIX)gcc
GCC_WARNS := -Wall -Wextra -Wconversion -pedantic -Wcast-qual -Wcast-align -Wwrite-strings
RISCV_GCC_OPTS ?= -static -mcmodel=medany -fvisibility=hidden -Tsections.ld -nostdlib -nolibc -nostartfiles ${GCC_WARNS}
RISCV_OBJDUMP ?= $(RISCV_PREFIX)objdump --disassemble-all --disassemble-zeroes --section=.text --section=.text.startup --section=.text.init --section=.data
RISCV_OBJCOPY ?= $(RISCV_PREFIX)objcopy -O verilog
RISCV_HEXGEN ?= 'BEGIN{output=0;}{ gsub("\r","",$$(NF)); if ($$1 ~/@/) {if ($$1 ~/@00000000/) {output=code;} else {output=1- code;}; gsub("@","0x",$$1); addr=strtonum($$1); if (output==1) {printf "@%08x\n",(addr%262144)/4;}} else {if (output==1) { for(i=1;i<NF;i+=4) print $$(i+3)$$(i+2)$$(i+1)$$i;}}}'
RISCV_COEGEN ?= 'BEGIN{printf "memory_initialization_radix=16;\n memory_initialization_vector=\n"; addr=0;} { gsub("\r","",$$(NF)); if ($$1 ~/@/) {gsub("@","0x",$$1);temp=strtonum($$1);for(;addr<temp;addr++){print "00000000,";}} else {printf "%s,\n", $$1; addr=addr+1;}} END{print "0;\n";}'

SRCS := $(wildcard  *.c)
OBJS := $(SRCS:.c=.o)
EXEC := main

.c.o:
	$(RISCV_GCC) -c $(RISCV_GCC_OPTS)  $< -o $@

${EXEC}.elf : $(OBJS)
	${RISCV_GCC}  ${RISCV_GCC_OPTS} -e entry $(OBJS) -o $@
	${RISCV_OBJDUMP} ${EXEC}.elf > ${EXEC}.dump

${EXEC}.tmp: ${EXEC}.elf
	$(RISCV_OBJCOPY) $<  $@

${EXEC}.hex: ${EXEC}.tmp
	awk -v code=1 $(RISCV_HEXGEN) $< > $@
	awk -v code=0 $(RISCV_HEXGEN) $< > ${EXEC}_d.hex

${EXEC}.coe: ${EXEC}.hex
	awk  ${RISCV_COEGEN} $< > $@
	awk  ${RISCV_COEGEN} ${EXEC}_d.hex > ${EXEC}_d.coe

.PHONY: all clean

all: ${EXEC}.coe

clean:
	rm -f *.o
	rm -f *.dump
	rm -f *.tmp
	rm -f *.elf
	rm -f *.hex
	rm -f *.coe
```

### 2.1 `awk` 做了什么

`objcopy -O verilog` 输出的文本类似：

```text
@00000000
130101ff ...
@00010000
...
```

`RISCV_HEXGEN` 的处理：

- 删除行尾的 `\r`；
- 遇到 `@` 开头的行，如果地址是 `@00000000`，标记为代码段，否则标记为数据段；
- 地址除以 4，输出成字地址；
- 数据行每 4 个字节一组，按小端拼成一个 32 位字输出。

所以 `main.hex` 的 `@` 是**字地址**，不是字节地址。数据段起始 `0x0010_0000` 经过 `% 262144` 后是 `@00000000`，所以 `main_d.hex` 是从 0 开始的独立数据镜像，装入 dmem 的 0 号单元即可。

`RISCV_COEGEN` 把 hex 转成 Vivado `memory_initialization_radix=16` 的 COE 格式，中间没写的地址补 `00000000`。

## 3. `sections.ld`

```ld
ENTRY(entry)
OUTPUT_FORMAT("elf32-littleriscv")

SECTIONS {
	. = 0x00000000;
	.text : {
		*(entry)
		main.o (.text)
		*(.text*)
		*(text_end)
	}
	etext = .;
	_etext = .;
	. = 0x00100000;
    .rodata : {
		*(.rodata*)
	}
	.data : {
		*(.data)
	}
	edata = .;
	_data = .;
	.bss : {
	_bss_start = .;
		*(.bss*)
		*(.sbss*)
		*(.scommon)
	}
	_stack_top = ALIGN(1024);
	. = _stack_top + 1024;
	_stack_pointer = .;
	end = .;
	_end = .;
	_heap_start = ALIGN(1024);
}
```

约定：

- 代码段从 `0x0000_0000` 开始，`entry` 放在最前面。
- 数据段从 `0x0010_0000` 开始，`.rodata`、`.data`、`.bss` 都在数据存储器。
- 栈顶 `_stack_pointer` 在数据段之后 1KB 对齐再加 1KB，示例程序把 `sp` 设成 `0x0011_fffc`。
- 堆从 `ALIGN(1024)` 开始。

硬件的数据存储器要覆盖到 `0x0011_ffff`，也就是至少 128KiB。示例工程按 128KiB 设计。

## 4. `sys.h`

```c
#define VGA_START    0x00200000
#define VGA_LINE_O   0x00210000
#define VGA_MAXLINE  30
#define LINE_MASK    0x003f
#define VGA_MAXCOL   70


void putstr(char* str);
void putch(char ch);

void vga_init(void);
```

`VGA_LINE_O` 是显示起始行寄存器，`LINE_MASK=0x3f` 表示显存 64 行环形缓冲；示例硬件可能只实现 32 行，以实际设计为准。`VGA_MAXLINE=30`、`VGA_MAXCOL=70` 对应屏幕可见区域。

## 5. `sys.c`

```c
#include "sys.h"


char* vga_start = (char*) VGA_START;
int   vga_line=0;
int   vga_ch=0;


void vga_init(){
    vga_line = 0;
    vga_ch =0;
    for(int i=0;i<VGA_MAXLINE;i++)
        for(int j=0;j<VGA_MAXCOL;j++)
            vga_start[ (i<<7)+j ] =0;
}

void putch(char ch) {
  if(ch==8) //backspace
  {
      //TODO
      return;
  }
  if(ch==10) //enter
  {
      //TODO
      return;
  }
  vga_start[ (vga_line<<7)+vga_ch] = ch;
  vga_ch++;
  if(vga_ch>=VGA_MAXCOL)
  {
     //TODO
  }
  return;
}

void putstr(char *str){
    for(char* p=str;*p!=0;p++)
      putch(*p);
}
```

说明：

- 行步长是 128，不是 70；`(i<<7)+j` 直接对应显存地址 `{row, col}`。
- `vga_init` 只清 30×70 个可见字符，没有清 32 行缓冲的其余部分；如果硬件用 32 行环形缓冲，滚屏前最好清空整块。
- `putch` 的退格、回车、行尾换行都是 TODO，正是 lab12 要补的部分。
- 写显存用 `char`，编译器生成 `sb`，硬件要支持字节写。

## 6. `main.c`

```c
#include "sys.h"


char hello[]="Hello World 2022!\n";

int main();

//setup the entry point
void entry()
{
    asm("lui sp, 0x00120"); //set stack to high address of the dmem
    asm("addi sp, sp, -4");
    main();
}

int main()
{
    vga_init();

    putstr(hello);
    while (1)
    {
    };
    return 0;
}
```

要点：

- `entry` 用 `lui sp, 0x00120` 得到 `0x0012_0000`，再减 4 得到 `0x0011_fffc`，这是数据段顶端的栈。
- 裸机启动时 `sp` 是全零，不初始化的话 `main` 第一条调整 `sp` 的指令会得到 `0xffff_fff0`，访问到不存在的地址。
- `main` 不允许返回，末尾必须有死循环。`entry` 在 `main` 返回后会恢复寄存器并 `ret`，系统状态会不正常。

`main.dump` 里可以检查入口：

```text
00000000 <entry>:
   0: ff010113  addi sp,sp,-16
   4: 00112623  sw ra,12(sp)
   8: 00812423  sw s0,8(sp)
   c: 01010413  addi s0,sp,16
  10: 00120137  lui sp,0x120
  14: ffc10113  addi sp,sp,-4
  18: 018000ef  jal ra,30 <main>
```

## 7. `mul.c`

```c
unsigned int __mulsi3(unsigned int a, unsigned int b) {
    unsigned int res = 0;
    while (a) {
        if (a & 1) res += b;
        a >>= 1;
        b <<= 1;
    }
    return res;
}

unsigned int __umodsi3(unsigned int a, unsigned int b) {
    unsigned int bit = 1;
    unsigned int res = 0;

    while (b < a && bit && !(b & (1UL << 31))) {
        b <<= 1;
        bit <<= 1;
    }
    while (bit) {
        if (a >= b) {
            a -= b;
            res |= bit;
        }
        bit >>= 1;
        b >>= 1;
    }
    return a;
}

unsigned int __udivsi3(unsigned int a, unsigned int b) {
    unsigned int bit = 1;
    unsigned int res = 0;

    while (b < a && bit && !(b & (1UL << 31))) {
        b <<= 1;
        bit <<= 1;
    }
    while (bit) {
        if (a >= b) {
            a -= b;
            res |= bit;
        }
        bit >>= 1;
        b >>= 1;
    }
    return res;
}
```

这三个函数来自 GCC 的软件乘除法实现。有符号乘除还需要 `__divsi3`、`__modsi3`、`__muldi3` 等，按实际用到的运算补。

## 8. 编译与加载的常见问题

1. **链接报 `undefined reference to __mulsi3`**：把 `mul.c` 加入编译。
2. **程序跑飞，`main` 第一条指令就访问非法地址**：检查 `entry` 是否设置 `sp`，以及链接脚本是否把 `entry` 放在 `0x0`。
3. **`main.hex` 为空或只有 `@00000000`**：检查 `objcopy`、`awk` 是否可用，`main.elf` 是否真的包含代码。
4. **数据不对**：检查 `main_d.hex` 是否生成、`$readmemh` 是否加载、数据存储器是否覆盖 `0x0010_0000`–`0x0011_ffff`。
5. **开了 `-O2` 后轮询失效**：MMIO 指针加 `volatile`，例如 `#define KBD_STATUS (*(volatile unsigned int *)0x00300004)`。
6. **字符写进显存但显示错位**：确认行步长 128、列范围 0–69、字符地址是 `(row<<7)+col`。
7. **C 库函数缺失**：没有 libc，`strcmp`、`strlen`、`printf` 都要自己实现，或者从 PA/AM 移植。
8. **指令集不匹配**：用 `objdump -d main.elf` 检查是否出现 `mul`、`div`、`c.addi` 等 RV32I 不支持的指令。
9. **`awk: function strtonum never defined`**：Ubuntu 默认的 `mawk` 不支持 `strtonum()`，装 `gawk`，或把 `awk` 指向 `gawk`。`riscv32:12` 镜像里已经装了 `gawk`。
10. **`main.hex` 第一条不是入口指令**：Ubuntu 22.04 的交叉 GCC 默认生成 `.note.gnu.build-id`，链接到地址 0，把 `.text` 推到 `0x24`。加 `-Wl,--build-id=none`。
11. **数据段地址对不上**：`main_d.hex` 从 `@00000000` 开始，是独立数据镜像；dmem 用 `addr[16:2]` 索引，`0x0010_0000` 映射到 0。不要把它当成从 `@00004000` 开始。
12. **C 编译器默认生成 RV64**：`riscv64-linux-gnu-gcc` 要显式加 `-march=rv32i -mabi=ilp32`，否则链接出的指令或库不匹配。
