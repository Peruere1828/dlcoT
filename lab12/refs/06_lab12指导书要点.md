## 1. 实验目标

在 Nexys A7-100T 的 FPGA 上实现一个简单的计算机系统，能运行指令并处理一定量的输入输出。最终完成基本的 terminal：键盘输入命令，显示器输出结果。手册内容只是设计参考，可以按兴趣裁剪和修改。

## 2. 硬件部分

CPU 与外设建议使用内存映射：预先规定某些地址对应外设的输入或输出，CPU 用普通 `load`/`store` 访问。硬件不需要知道地址含义，只要把正确的地址、读写信号放在总线上；数据含义由软件处理，外设只关注自己的一小块地址空间。

### 2.1 外设内存映射

CPU 数据地址 32 位，可寻址 4GB。前一实验的数据存储只占 128KB，可以重新规划：

- 高 12 位全零，即 `0x0000_0000`–`0x000F_FFFF`，分给指令存储器；
- 高 12 位为 `0x001`，即 `0x0010_0000` 起，分给数据存储器，放常量、全局变量、堆和栈；
- 每个外设用高 12 位区分，例如 `0x002` 开头给显示器，`0x003` 开头给键盘。

指令存储器和数据存储器在系统中是分开的，也可以统一编址。CPU 读写时把 32 位地址放在数据地址总线上，用高 12 位判断访问哪一片存储。写入时只把对应存储的写使能置有效；读取时可以同时读多片，再按高 12 位选择数据送上 CPU 数据总线。思路与实验十用四片 RAM 拼 32 位数据类似。

数据存储段可以用实验十的大容量 RAM；外设容量小，可以用手写 RAM 或寄存器实现，注意读写时钟。

### 2.2 外设读写类型

映射到外设的内存通常需要两个以上读写端口，一套给 CPU，一套给外设，可能出现读写冲突。按外设对存储的读写要求分类：

- **CPU 只读型**：定时器、板上开关等。空间很小，一般 32 或 64bit。把外设对应的 `wire` 在时钟上升沿赋给寄存器，CPU 读地址匹配时把寄存器内容放上数据总线。
- **CPU 只写型**：显示器、LED、七段数码管等输出设备。CPU 总在上升沿写入，外设可以在下降沿读取并锁存，用于驱动外设。容量小时也可以用类似寄存器堆的方式异步读。
- **CPU 同时需要读写型**：同一周期内 CPU 和外设不能同时写同一地址。这种情况很少，一般可以划分成 CPU 只读或只写区域。键盘空间是例子。

C 语言的 `volatile` 用于防止编译器过度优化。CPU 只读型变量的值可能被外设改变，CPU 轮询 `while(data==0){}` 时，编译器在 `-O2` 下可能认为循环无用，只判断一次。给变量加 `volatile` 可以避免。

### 2.3 常见外设实现

- **LED**：CPU 只写，32 位寄存器，对应比特直接 `assign` 给 LED。软件可以在自己的存储空间保留一份 LED 状态副本，修改副本后整体写入。
- **七段数码管**：CPU 只写 BCD 码，同 LED，用 32 位寄存器。
- **定时器**：CPU 只读。用系统时钟分频出 1ms 或 1μs 定时信号，计数器累加，每个时钟上升沿写入定时器地址。宽度可以 32 或 64 位。CPU 用 `load` 读取从开机到当前的毫秒或微秒数，可用于时钟、计时、操作系统的定时功能。
- **开关**：CPU 只读，把开关接到特定寄存器，`load` 读取。
- **显示器**：CPU 只写。分配字符显存，每 8bit 一个 ASCII 码。64 行×64 列字符缓存只需 4096Byte。显存要支持不同位宽的 `sb`、`sh`、`sw`。另外可以分配控制寄存器，例如起始行号用于滚屏、颜色寄存器控制字符和背景颜色。CPU 在上升沿写显存和控制寄存器；显示部分像实验九，从显存读 ASCII 并输出。滚屏时显示硬件从给定起始行开始读后续 30 行，行号可以模 64 循环，改变起始行即可滚屏。建议显示器只忠实显示显存中的 ASCII，滚屏清零由软件做。显示器可以用自己的 25MHz 时钟读显存；CPU 写入慢不影响显示按自己的节奏读。
- **键盘**：建议用循环缓冲区。分配 16 或 32 个扫描码槽位（4 字节），设置头指针 `head` 和尾指针 `tail`。键盘硬件是数据生成者，写缓冲区；CPU 是消费者，读缓冲区。头指针只有 CPU 写，尾指针和缓冲区只有键盘写，因此 CPU 只写区和外设只写区分开，不会读写冲突。键盘收到按键时读 `head` 和 `tail`，如果 `tail == head-1` 表示缓冲区满，不能写；否则在 `tail` 写扫描码，`tail+1`。CPU 检查 `head` 和 `tail`，相等表示空；不相等时把 `head` 指向的扫描码拷入内存，`head+1`。这样 CPU 忙时不会丢键，也能非阻塞读取。扫描码到 ASCII 的转换可以由软件做；如果只需要 ASCII，也可以由硬件转换，灵活性差一些。

显存组织示意和键盘缓冲区示意见 `lab12.pdf` 图 12-1、图 12-2。

### 2.4 内存映射实现

数据 RAM 用双口方式：独立读地址、读数据输出、读时钟，以及写地址、写数据输入、写时钟。读写完全分离，可以分别设计。不同外设用单独的 RAM 或寄存器实现，把外设的数据线、地址线和 CPU 的数据线、地址线接到对应读/写接口。

数据存储只与 CPU 相连，读写地址、时钟、`memop` 直接接 CPU：

```verilog
dmem datamem(.rdaddr(drdaddr),   // CPU 读地址
             .dataout(ddataout), // 数据存储读数据输出
             .wraddr(dwraddr),   // CPU 写地址
             .datain(ddatain),   // CPU 写数据输入
             .rdclk(drdclk),     // CPU 读时钟
             .wrclk(dwrclk),     // CPU 写时钟
             .memop(dop),        // CPU 数据操作类型
             .we(datawe));       // 数据存储写使能
```

地址分配靠写使能和读数据选择：

```verilog
assign datawe = (dwraddr[31:20] == 12'h001) ? dwe : 1'b0;
assign ddata  = (drdaddr[31:20] == 12'h001) ? ddataout :
                ((drdaddr[31:20] == 12'h003) ? keymemout : 32'b0);
```

写地址高 12 位是 `0x001` 时才允许写；读地址高 12 位是 `0x001` 时选数据存储，是 `0x003` 时选键盘。显示器 CPU 不读，所以没有读通路。

## 3. 软件部分

建议用 RISC-V C 工具链编译，用 C 写整体代码。

### 3.1 编译过程

用 `riscv32-unknown-elf` 工具链，自己写 Makefile。手册给出示例，包含：

- 工具链前缀、GCC 告警级别；
- `-static -mcmodel=medany -fvisibility=hidden -Tsections.ld -nostdlib -nolibc -nostartfiles`；
- `objdump`、`objcopy -O verilog` 参数；
- 用 `awk` 把 hex 文本转成 Verilog 可读的 4 字节 hex，并分开代码段和数据段；
- 用 `awk` 生成 Vivado 的 coe 文件，分别初始化指令和数据存储器。BRAM IP 可以用 coe 初始化，但每次改 coe 后要重新生成 IP；Vivado 打包 IP 时会把 coe 转成 mif，编译时用 mif 初始化内存，也可以直接生成 mif 修改 IP 初始化文件。

`sections.ld` 规定可执行文件地址映射：

- `ENTRY(entry)`，`OUTPUT_FORMAT("elf32-littleriscv")`；
- `. = 0x00000000`，`.text` 从 0 开始，`entry` 放最前面，`main.o(.text)` 随后；
- `. = 0x00100000`，`.rodata`、`.data`、`.bss` 从数据段开始；
- `_stack_top = ALIGN(1024)`，栈顶再留 1KB，`_heap_start = ALIGN(1024)`。

硬件 reset 后从 `0x00000000` 取指，所以代码段必须从 0 开始，入口函数必须在最前。数据段从 `0x00100000` 开始，与硬件规定一致。Makefile 用 `awk` 把非代码段数据统一放进 `main_d.mif` 初始化数据存储。内存映射的输出地址空间不需要初始化，二进制文件中不出现。

### 3.2 Hello World 示例

`main.c` 包含自定义头文件，用全局数组保存字符串，编译后放数据段。`entry` 负责初始化堆栈并调用 `main`：

```c
void entry()
{
    asm("lui sp, 0x00120"); // set stack to high address of the dmem
    asm("addi sp, sp, -4");
    main();
}
```

裸机启动时 `sp` 全零，不初始化的话 `main` 第一句调整 `sp` 会得到 `0xfffffff0`，访问不存在的地址。`entry` 把 `sp` 设到数据段顶端 `0x0011fffc`。`main` 不允许返回，必须在内部死循环。

`sys.h` 规定 VGA 缓存起始地址、行列数等：

```c
#define VGA_START    0x00200000
#define VGA_MAXLINE  30
#define VGA_MAXCOL   70

void putstr(char* str);
void putch(char ch);
void vga_init(void);
```

`sys.c` 实现 `vga_init`、`putch`、`putstr`。`vga_init` 清空 30×70 个字符；`putch` 里退格和回车是 TODO，行尾处理也是 TODO，这些是 lab12 要补的。

如果需要实时更新数据段，建议修改硬件，增加一个只读数据存储，在 `main` 起始时用 `memcopy` 把只读存储拷到实际数据存储器。

## 4. 调试工具

综合实验编译一次十几分钟到半小时，软件改动也要重编，硬件内部信号不可见，调试成本高。手册介绍用串口实现软件下载、CPU 重启，并提供示例代码。

### 4.1 串口背景

串行接口逐比特在单条线路上传输，数据线少，FPGA 和嵌入式设备常用串口调试。旧台式机的 9 针 RS232 引脚和接线见 `refs/01`。UART 是异步串行，收发两端不需要时钟同步，接收端自己产生时钟采样。典型帧：起始位（高变低）、8 位数据、1 位校验、1 位停止位。波特率是每秒 bit 数，常见 9600、19200、38400、57600、115200。参数需要双方约定。

Nexys A7-100T 用 FT2232 做 USB-UART 桥接，串口和下载共用 USB 线，互不干扰。TXD、RXD、CTS、RTS 接 FPGA 的 C4、D4、D3、E5；CTS、RTS 用于硬件流控，可以不管，CTS 置低即可。电脑侧装串口调试助手，连接 USB 后出现串口，一般是 COM4。板载两个黄色 LED 指示串口收发。

### 4.2 串口收发设计

发送端：100MHz 时钟经 `clkgen #(115200)` 产生发送时钟，8 位数据加起始位、奇校验、停止位，用移位寄存器逐位发送。输入 `tx_enable`，输出 `tx_ready`，忙时忽略新的发送请求。代码见 `refs/01`。

接收端：先对 `txd_in` 同步，检测起始位下降沿，产生与发送端一致的接收时钟，在每个 bit 中间采样。收满 11 位后检查起始位和奇校验，输出 8 位数据和 `rx_finish`，用 `rx_ready` 握手。代码见 `refs/01`。

### 4.3 UART 调试功能

`uart_port` 通过串口发送、接收模块通信，根据输入字符执行调试动作，控制 CPU 和存储器。示例提供 CPU reset、指令存储器加载、数据存储器加载。可以扩展单步、显示 PC、显示存储器、显示寄存器等。

接口：

```verilog
module uart_port(input clk,
                 input clk100m,
                 output rxd_out,
                 input txd_in,
                 output reg [31:0] dbgdata,
                 input rst,
                 output [31:0] instaddr,
                 output reg [31:0] instdata,
                 output reg iwe,
                 output [31:0] dataaddr,
                 output [31:0] mdata,
                 output reg dwe,
                 output reg cpuhalt,
                 output reg cpureset);
```

- `clk` 建议与 CPU 时钟一致，`clk100m` 给串口模块；
- `dbgdata` 是 32 位调试信息，可以接七段数码管；
- `instaddr`、`instdata`、`iwe` 控制指令存储器；
- `dataaddr`、`mdata`、`dwe` 控制数据存储器；
- `cpuhalt`、`cpureset` 控制 CPU 暂停和复位。

控制 CPU：把 `cpuhalt` 取反后与 CPU 时钟相与，`cpuhalt=1` 时 CPU 时钟为 0，CPU 停止；`cpureset` 与 `BTNC` 一起作为 CPU 复位。

控制存储器：`uart_halt` 有效时，指令存储器的地址、时钟、输入数据、写使能都由调试模块控制，CPU 停下时可以任意读写。注意存储器时序，UART 时钟可能要错开半周期，保证数据有效时读写。数据存储器同理。

串口收发用 `tx_buf`、`rx_buf` 两个 FIFO，接收只向队尾添加、递增 `rx_tail`，发送从 `tx_head` 取数据。调试器时钟远高于 115200Hz，示例没有考虑溢出。

手册提醒：Verilog 缓冲区不是 C 数组，不要在同一个时钟周期对同一缓冲区的不同位置多次读写，否则综合时无法映射成 RAM。要通过串口输出多个字符时，分多个周期每次写一个。实现复杂时，建议用七段数码管输出调试信息，而不是串口直接输出。

状态机：初始等待单字符命令，`i` 加载指令存储器，`d` 加载数据存储器，`r` 重启 CPU。匹配后进入对应状态。加载时先暂停 CPU，等待串口传 `.hex` 文件。以 `@` 开头的行是十六进制地址，状态机解析地址并设置 `instaddr`；数据部分每行一个存储器单元，状态机转换后通过写数据端口和写使能写入，地址加一。传完输入 `q` 结束加载，复位 CPU 并用新代码执行。

### 4.4 思考问题

- 如果要实现单步执行，如何通过 `cpuhalt` 控制 CPU 只执行一个周期就停止等待？
- 如果把 CPU 的指令地址送给 UART 调试模块，是否可以实现断点？
- 如何查看指令和数据存储器中给定地址的内容？
- 如何查看 CPU 中寄存器内容？需要对 CPU 和 UART 调试器做哪些改造？
- 在 Linux 下，是否可以用 Makefile 脚本直接串口加载代码？

## 5. 实验验收要求

本实验分组进行，只做上板验收，演示完整的计算机系统。必须实现：

1. 接受键盘输入并回显在屏幕上；
2. 支持换行、删除、滚屏；
3. 命令分析，根据输入执行子程序并输出结果：
   - 输入 `hello`，显示 `HelloWorld!`；
   - 输入 `time`，显示时间；
   - 输入 `fib n`（手册写作 `fibn`），计算斐波那契数列并显示结果；
   - 输入未知命令，输出 `UnknownCommand`。

这样的系统已经具备 20 世纪 80 年代末个人计算机的基本能力。附加功能可选：

硬件：

1. 扩展 CPU 指令，支持系统调用、乘除法或自定义指令；
2. 支持简单中断；
3. 增加外设，控制 LED、七段显示等；
4. 增加显示器复杂度，提供简化图形界面；
5. 用 AXI Lite 连接外设，模块化，增加 DDR、串口、SD 卡等。

软件：

1. 输入简单表达式，如 `(9+6*6)-3`，输出结果；
2. 实现简单 C 库函数，移植 PA 的 AM 代码；
3. 编译运行 benchmark，评估 CPU 性能。
